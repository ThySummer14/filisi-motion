# 架构与工程边界

## 选择

本版用原生 ES modules 与 Canvas2D，不依赖 WebGL，不需要打包器或第三方运行库。目标是先验证「编辑 → 动画 → 存储 → 渲染」最小可用闭环，而不是模拟完整 AE 的菜单。

单个工程存储合成参数、从底至顶的图层数组、嵌入图片以及逐属性数值关键帧。画面由任意时间点纯取样产生，预览和导出复用同一个渲染器。

## 模块边界

- `core.js` 不依赖 DOM，负责数据模型、校验、时间插值和 undo/redo。
- `render.js` 负责图片缓存、Canvas2D 绘制和旋转缩放后的命中测试。
- `gif.js` 按固定 RGB332 全局调色板写 GIF89a，literal LZW 每 200 像素重置字典。好处是简单、可验证、无运行依赖；代价是压缩率较低，不应用作专业视频交付。
- `app.js` 处理 DOM 交互、浏览器保存和导出。工程输入进行白名单校验，文字通过转义插入 DOM，拒绝外部图片 URL / SVG。

## 视频管线

MediaRecorder 从离屏画布实时采集；合成的 FPS 是请求帧率，不是逐帧编码保证。浏览器调度和机器负载会影响帧数，导出不可宣称无损或帧精确。当前无音频。

后续优先评估 WebCodecs 配合许可清楚的 WebM / MP4 muxer，用离线时间步进提升可预测性；需要确认编码器能力、文件兼容、取消机制和内存上限。WebM 不应伪装为 MP4，更改扩展名不能转码。

## 数据与内存

本地自动存档有浏览器配额限制；完整历史使用最多 60 份 JSON 快照。含较多图片的项目不适合长期依赖此模型。后续可用资产表 + 引用计数 + 增量历史，并用 IndexedDB 保存。

v1 工程校验限制图层数、尺寸、时长、关键帧数、图片格式和数据长度，拒绝 NaN / Infinity。这里没有任意 JavaScript 表达式执行。

## 测试策略

Node 测试覆盖数值与存储边界；GIF 样本通过独立解码器检查；浏览器验收覆盖真实 UI、保存导入和动画文件。浏览器兼容不能从单元测试推导。具体已验证内容及未验证项目记录在 `docs/QA.md`。

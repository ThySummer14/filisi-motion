# 长时间轴：0.4 开发预览

这一轮针对连续多镜头工程：同一个视频源被切成多个片段，原声放在独立连续音轨。工程文件仍是兼容的 v3 格式；不把片段数量当作素材副本数量。

## 解码工作集

预览与视频取帧保留当前可见片段，并预加载下一组同时开始的片段。串行 16 段画面加一条连续音轨，在普通位置只需当前画面、下一镜和原声三个解码器；最后一镜只需两个。过去的片段退出工作集时会暂停、断开音频节点并释放媒体元素。

重叠合成会保留所有当前可见片段；下一时刻若有多层同时开始，也会一起准备。**三个不是全局硬上限**，不能通过丢掉可见图层来减少内存。素材 Blob 仍在本机缓存中；释放解码器不删除素材或历史记录。切换工程还会释放已持久化且不再使用的内存缓存引用；IndexedDB 中的素材保留，未持久化的素材不被丢弃。

- 播放跨切点时保留连续音轨及其已预排的增益，不重新启动背景音乐。
- 新片段必须完成元数据读取和初始定位，才能开始播放或显示。
- 随机定位只等待当前工作集；后来的定位请求可以取代旧请求。
- 媒体状态的提示文字显示当前解码器数量、最近定位耗时；支持的浏览器还显示近似 JavaScript 堆大小。后者不包含原生解码器，也不是浏览器进程的硬内存上限。

## 时间线操作

缩放上限提高到 20 倍。刻度随缩放选择合适间隔，并对齐工程帧率，避免长片放大后仍只有十个稀疏刻度。

「跟随」控制播放或数值定位时是否滚动到播放头。修改缩放会以播放头为中心重新安排视口。图层名称仍固定在左侧。

复制视频 / 音频片段时保留画面位置、源入点和关键帧。图形 / 文字复制仍保留原来的偏移行为。媒体片段数量上限也适用于复制，避免创建无法重开的超限工程。

## 工程加载

大工程读取期间显示忙碌状态。后来的打开 / 新建请求不会被较慢的旧请求覆盖；读取期间如果画布已修改，也不会悄悄用旧候选工程覆盖它。素材恢复失败时保留原工程，并报告真实失败原因，不再显示误导性的「工程已打开」。

## 验证边界

本轮已加入工作集、跨切点音轨连续、过时加载释放、未就绪媒体禁止播放、动态刻度和视口跟随的 Node 测试。它们使用模拟媒体对象验证生命周期；模拟结果不单独代表真实浏览器性能。当前已完成的桌面 Chrome 长片实测与局限见 [QA](QA.md)。

WebM 仍是实时录制，原生媒体启动延迟与视频掉帧问题没有因工作集优化而自动解决。实验性离线 WAV 是独立的音频输出路径，见 [音频说明](OFFLINE_AUDIO.md)。
